# Рефакторинг инструментов холста

План следующего этапа для `refactor-interfaces-architecture` после коммита `9816840`. Ветка уже связывает эффекты с контроллерами и представлениями через `EFFECT_REGISTRY`. Следующий шаг — применить этот подход к инструментам холста и поручить передачу событий одному адаптеру. Код инструмента должен читаться и проверяться как последовательность действий от начала до завершения жеста. [Архитектура эффектов](ARCHITECTURE.md#featureseffects) · [Реестр эффектов](../src/features/effects/registry.ts)

## 1. Границы ответственности

| Участок                             | Ответственность                                                                                                                                                                                  |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `features/canvas-tools/`            | Классы `SelectTool`, `BrushTool`, `AllTool` и реестр контроллеров с их View. Классы определяют геометрию маски, поведение инструмента и подсказки.                                               |
| `features/block-transform/`         | `BlockTransferController` и `BlockRepeatController` владеют своими этапами, геометрией по блокам компонента, контурами и правилами применения. `EFFECT_REGISTRY` остаётся точкой их регистрации. |
| Компонент холста и адаптер в `ui/`  | Нормализация координат, выбор обработчика при нажатии, захват и освобождение указателя, фокус, курсоры и отрисовка контуров.                                                                     |
| `CanvasToolbar` и View инструментов | Кнопки и контекстные контролы из реестра, например размер кисти и общая привязка DCT/MCU. View отвечает за оформление и размещение подсказок.                                                    |
| `App` и прикладной слой             | Выбор эффекта, текущая рабочая маска, Auto Apply, единый путь Preview/Apply, история и работа с JPEG.                                                                                            |

В `EffectToolbarConfig.tools` View эффекта передаёт список ID типа `readonly MaskTool[]`. Название, иконку, хоткей и контекстные контролы берём из записи инструмента. Кнопки и A/B/M вызывают один путь `activateTool(id)` с проверкой доступности. Оставляем один тип `MaskTool` для реестра, тулбара и `workspaceReducer`. У жестовых эффектов управление холстом берётся из `controller.gestures`. У панельных эффектов холст доступен для навигации.

Выбор режима холста и выбор эффекта независимы. При переключении между масочными эффектами редактор сохраняет выбранный инструмент и рабочую маску. При переходе на жестовый или панельный эффект контур рабочей маски скрывается. Применение эффектов использует текущие операции, History и worker. ## 2. Контракты

### Адаптер холста

На границе с DOM достаточно одного контракта. `image` содержит координаты пикселей исходного JPEG после обратного преобразования масштаба и EXIF. Координаты за границей кадра сохраняются с `inside: false`. `image: null` означает, что точку вычислить невозможно. Для панорамирования используются клиентские координаты.

```ts
interface ImageSample {
  readonly point: ImagePoint;
  readonly inside: boolean;
}

interface CanvasPointerInput {
  readonly clientPoint: { readonly x: number; readonly y: number };
  readonly image: ImageSample | null;
}

interface CanvasToolHint {
  readonly text: string;
  readonly keyboard?: string;
}

interface CanvasGesture {
  move(input: CanvasPointerInput): void;
  end(input: CanvasPointerInput): void;
  cancel(): void;
}

interface CanvasInteraction {
  begin(input: CanvasPointerInput): CanvasGesture | null;
  getHint(): CanvasToolHint | null;
  hover?(sample: ImageSample | null): void;
  handleKey?(input: CanvasKeyInput): boolean;
}
```

Адаптер связывает эти методы с типизированным контроллером и его контекстом. Например, результат жеста эффекта передаётся владельцу его настроек, а результат жеста кисти — владельцу текущей маски. `CanvasGesture` уже привязан к владельцу, выбранному при `begin`. `pointermove` и `pointerup` используют этот объект и `pointerId` сессии.

`CanvasKeyInput` содержит клавишу, модификаторы и признак фокуса холста. Адаптер подавляет действие браузера только для обработанной клавиши. Необязательные `hover` и `handleKey` позволяют холсту вызывать наведение Brush и клавиатуру Select по доступности метода.

### Масочные инструменты

Реестр хранит контроллеры и View. Изменяемые точки, начальный якорь и черновик принадлежат конкретной сессии. `AllTool` регистрируется как команда `createMask(inspection): Result<SpatialMask>`. Для Brush и Select используется следующий контракт.

```ts
interface MaskToolContext {
  readonly inspection: JpegInspection;
  readonly componentIndex: number;
  readonly grid: JpegSelectionGrid;
  readonly brushSize: number;
}

type MaskDraft =
  | { readonly kind: "rectangle"; readonly selection: SpatialSelection }
  | {
      readonly kind: "brush";
      readonly strokes: readonly (readonly ImagePoint[])[];
      readonly radius: number;
    };

interface MaskGesture {
  move(sample: ImageSample): Result<void>;
  getDraft(): MaskDraft | null;
  end(sample: ImageSample | null): Result<SpatialMask | null>;
  cancel(): void;
}

interface MaskToolController {
  begin(
    context: MaskToolContext,
    sample: ImageSample,
  ): Result<MaskGesture | null>;
  getHint(context: MaskToolContext): CanvasToolHint | null;
}
```

`null` при успешном `begin` означает отказ от захвата указателя. `getDraft` отдаёт снимок для отрисовки. `end` отдаёт готовую маску, пустой результат или типизированную ошибку. Курсор кисти при наведении можно получать через отдельный метод Brush и показывать в компоненте холста.

В реестре `kind` различает команду и контроллер жеста. Проверка через `Record<MaskTool, MaskToolEntry>` гарантирует наличие всех объявленных инструментов.

```ts
const MASK_TOOL_REGISTRY = {
  all: { kind: "command", controller: new AllTool(), view: AllToolView },
  brush: { kind: "gesture", controller: new BrushTool(), view: BrushToolView },
  select: {
    kind: "gesture",
    controller: new SelectTool(),
    view: SelectToolView,
  },
} satisfies Record<MaskTool, MaskToolEntry>;
```

Select переиспользует построение прямоугольника для указателя и клавиатуры. Стрелки перемещают клавиатурный курсор по видимым DCT-блокам выбранного компонента с учётом EXIF, Enter задаёт якорь и завершает выделение, Escape очищает маску и якорь. Курсор и якорь хранит сессия Select в рабочей области. Ctrl/⌘+A в Select вызывает ту же команду создания полноразмерной маски, что и All, и сохраняет активным Select.

Все завершённые маски принимает `commitMask(mask, trigger)` в редакторе. Завершение Brush или Select заменяет рабочую маску и проверяет Auto Apply ровно один раз, передавая готовую маску явно. Успешное добавление операции очищает рабочую маску, ошибка применения оставляет её для исправления. All и Ctrl/⌘+A только задают маску. Изменения черновика обновляют контур. Для Preview и сохранения проекта редактор использует рабочую маску. [Модель маски](../src/document/masks.ts) · [Геометрия JPEG](../src/jpeg/block-geometry.ts) · [Преобразование EXIF](../src/application/preview-orientation.ts)

### Общий жизненный цикл

1. На `pointerdown` выбираем панорамирование для средней кнопки или основной кнопки с пробелом. Иначе для основной кнопки берём текущий инструмент из реестра или адаптируем `gestures` выбранного эффекта. Новые нажатия во время активной сессии игнорируются.
2. При успешном `begin` захватываем указатель и сохраняем `{ pointerId, gesture }`. Select может начать жест за границей кадра и обрезает прямоугольник по изображению. Brush и жесты Block Transform начинаются внутри кадра.
3. Только события нужного `pointerId` продвигают сессию. На `pointerup` удаляем её из адаптера перед вызовом `end` и освобождаем захват. На `pointercancel` и `lostpointercapture` таким же образом забираем активную сессию и вызываем `cancel`. Это защищает от повторного завершения после освобождения захвата.
4. При смене инструмента, эффекта, открытого документа, компонента или сетки отменяем жест перед сменой контекста. Для Brush размер фиксируется на время мазка. Сброс выделения и Restore Selection также завершают прежнюю сессию перед обновлением маски. Отмена очищает временную геометрию и панорамирование и сохраняет последнюю рабочую маску.

При переносе сценариев сводим `selectionStart`, `brushPoints`, `activeGesture` и начало панорамирования к одному владельцу жеста. Отдельное состояние рабочего документа и подтверждённых настроек эффекта остаётся доступно между жестами. [Текущие обработчики в App](../src/App.tsx#L1169)

## 3. Block Transfer и Block Repeat

Block Transfer интегрируется через общий `CanvasGesture`. При выборе эффекта адаптер берёт существующий `EffectGestureController<BlockTransferSettings>` и передаёт ему `begin`, `move`, `end`, `cancel`. Двухэтапный сценарий остаётся внутри контроллера.

| Состояние              | Что делает следующий жест                                               | Что происходит при завершении                                                                                                                             |
| ---------------------- | ----------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Источник отсутствует   | Строит прямоугольник видимых 8×8 DCT-блоков выбранного компонента.      | Сохраняет область в `settings.source` для второго жеста.                                                                                                  |
| Источник выбран        | По точке указателя позиционирует назначение и показывает его контур.    | Допустимое назначение применяет один `block-transfer` через существующий Apply с финальным набором параметров. Источник доступен для следующего переноса. |
| Назначение недопустимо | Показывает контур недопустимой области, если геометрию можно построить. | Сохраняет источник, чтобы следующим жестом выбрать другое назначение.                                                                                     |

Второй жест Transfer можно начать в любом месте изображения. Положение указателя задаёт блок назначения. Copy обрезает область назначения по видимым границам компонента. Swap сохраняет размер и следует текущей проверке границ и пересечений. Для контура и операции переиспользуем `getBlockTransferOperation` и существующие проверки, чтобы показать геометрию применяемого переноса. Источник и назначение хранятся в настройках Transfer, где координаты заданы в блоках компонента.

Контекст адаптера привязан к ID эффекта и экземпляру открытого документа. `patch` передаётся настройкам эффекта-владельца. При `end` в Apply передаётся этот же финальный `patch`, чтобы применить параметры из события отпускания даже до рендера React. При `cancel` применяется только возвращённая контроллером очистка временной геометрии. У текущего Transfer отмена жеста назначения возвращает пустой патч. При переносе добавляем очистку временного назначения с сохранением источника.

Кнопка New source и R отменяют текущий жест и сбрасывают источник, назначение и их черновики. Смена компонента сначала отменяет текущий жест, затем сбрасывает эти области через существующий `resetForComponentChange`.

Block Repeat использует тот же адаптер событий. Первый жест выбирает один блок, второй начинается в этом блоке и задаёт первое назначение и смещение. Операция добавляется в историю по кнопке Apply block repeat. Общий адаптер интерпретирует `GestureOutcome.apply`, правила его выставления определяет контроллер эффекта. [Block Transfer](../src/features/block-transform/effects/block-transfer.controller.ts) · [Block Repeat](../src/features/block-transform/effects/block-repeat.controller.ts) · [Контракты жестовых эффектов](../src/features/effects/types.ts)

## 4. Подсказки

Добавляем `getHint(context): CanvasToolHint | null` к контроллерам интерактивных масочных инструментов и к `EffectGestureController`. Адаптер привязывает контекст и отдаёт `getHint()` активного взаимодействия. Этот метод читает текущую фазу, выбранную сетку или настройки и возвращает данные для UI. Подсказка доступна до первого нажатия.

Для Transfer фаза определяется по `settings.source`.

```ts
getHint({ settings }: GestureContext<BlockTransferSettings>): CanvasToolHint {
  return settings.source
    ? {
        text: "Drag to position the destination. Release over a valid area to apply.",
        keyboard: "Press R to choose a new source.",
      }
    : { text: "Drag to select a source region on the DCT grid." };
}
```

Select сообщает, как начать и завершить прямоугольник указателем или клавишами. Brush может сообщить о привязке и завершении мазка. Repeat сначала описывает выбор одного блока, затем перетаскивание из него и применение кнопкой. Для панельного эффекта подсказка взаимодействия отсутствует.

Первое место отображения — рядом с тулбаром холста. View может вывести тот же результат в подходящем месте без повторения одной инструкции между холстом и правой панелью. Панель Transfer сохраняет координаты выбранного источника и пояснение режимов. У холста сохраняем `aria-describedby` для подсказки и отдельное live-объявление действий клавиатуры. Ошибки выполнения по-прежнему идут через действующий механизм сообщений об ошибках. Подсказка меняется при смене фазы и остаётся стабильной при движении внутри фазы. [Текущая панель Transfer](../src/features/block-transform/effects/block-transfer.view.tsx) · [Текущая панель Repeat](../src/features/block-transform/effects/block-repeat.view.tsx)

## 5. Порядок рефакторинга

1. **Восстановить исходную проверку ветки.** Удалить отдельный ID `engraving-vertical` из `EffectId`, `EFFECT_MENU` и устаревших ожиданий в `coefficient-brushes.test.ts` и `effect-operation-mapping.test.ts`. Поиск `rg -n 'engraving-vertical' src tests` должен вернуть пустой результат. Проверить оба значения `engrave-horizontal` и `engrave-vertical` через один Engraving, включая воспроизведение операции с вертикальным режимом. Проверить покрытие каталога тестом реестра и пройти `npm run check`.
2. **Провести Select и All через реестр.** Вынести адаптер событий и подключить подтверждение маски, клавиатурный сценарий и подсказку. Подключить панорамирование и текущие жесты эффектов к тому же владельцу сессии через адаптеры. Если перенос Brush идёт отдельным коммитом, на этом этапе передавать вызовы кисти через временный адаптер с текущей логикой.
3. **Проверить и завершить интеграцию Transfer и Repeat.** Добавить `getHint`, очистку при отмене, единый сброс через кнопку и R. Проверить, что контур назначения и итоговая операция используют одинаковую геометрию и что Repeat сохраняет явный Apply.
4. **Перенести Brush и контекстные контролы.** Использовать существующую привязку, промежуточные точки и предел 10 000 точек. Отделить черновик от рабочей маски, после переноса удалить временный адаптер. Перед этим закрыть дефект разорванного мазка отдельной правкой. `createBrushMaskFromStrokes` создаёт несколько фигур, а `isSpatialMask` принимает одну. Рекомендуемое решение — согласовать поддержку нескольких brush-сегментов в существующем массиве `shapes`, проверку общего лимита точек и полное копирование для Restore Selection. Проверить Preview, Apply и запись/чтение `.jpglitch`. До изменения допустимого содержимого файла согласовать совместимость со старыми сборками, которые принимают одну фигуру.
5. **Завершить перенос и обновить архитектурное описание.** Удалить из `App` старые ветки обработки и дубли хоткеев. `CanvasToolbar` и холст получают данные представления из реестра. Добавление следующего масочного инструмента сводится к контроллеру, View, регистрации и разрешению в нужном эффекте. [Действующее архитектурное описание](ARCHITECTURE.md)

## 6. Проверки для приёмки

- **Регистрация.** Все разрешённые ID масочных инструментов есть в реестре. Кнопка и хоткей одинаково переключают инструмент и отменяют текущий жест. Сочетания в полях ввода и диалоге сохранения сохраняют поведение.
- **Маршрутизация.** Второй указатель не меняет первый жест. Нормальный отпуск фиксирует результат один раз. Отмена, потеря захвата и смена контекста очищают черновик. Панорамирование оставляет историю и маску прежними.
- **Select и All.** Обрезка прямоугольника от внешней точки, пустой прямоугольник, DCT/MCU на 4:2:0 с нечётными размерами и EXIF, стрелки/Enter/Escape и Ctrl/⌘+A. При Auto Apply завершённое выделение добавляет одну операцию, а полноразмерная маска через All — только маску.
- **Brush.** Начало внутри кадра, выход и возврат без соединяющей линии, завершение у границы и превышение лимита. Маска с разрывом проходит применение, Restore Selection и сохранение после согласованной правки формата маски. Ошибка применения оставляет маску для исправления.
- **Transfer и Repeat.** Выбор источника и недопустимое назначение сохраняют число операций. Допустимый Transfer добавляет одну запись с координатами контура, а Repeat добавляет запись по кнопке Apply. Проверить обрезку Copy, ограничения Swap, Undo/Redo, сброс R и смену компонента во время жеста.
- **Подсказки.** Transfer показывает инструкцию выбора источника при активации, инструкцию назначения после выбора и первую инструкцию после New source. Проверить текст и доступное описание холста для Select, а также стабильность подсказки при движении указателя.

Проверить контроллеры и переходы состояний в Vitest, затем пройти основные сценарии в браузере на синтетическом JPEG из `tests/fixtures/`. Итоговая проверка — `npm run check`.
