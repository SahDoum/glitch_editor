# Импорт и жизненный цикл Worker-клиентов

Источник: `docs/REFACTOR.md`, обновлённая ветка `e497517`.

## Цель
Общий импорт байтов JPEG для File и проверенного источника проекта; передавать EXIF orientation и color model, убрать повторный хеш/разбор. Привязать coefficient reader к источнику, закрывать все pending при сбое и запретить использование завершённого клиента. Убрать лишние копии, валидировать ответы, cancellation и listeners. Изменения App передать владельцу editor-session, project API согласовать history-project.

## Зона ответственности
src/application/import-jpeg.ts; src/application/coefficient-reader.ts; src/jpeg/inspect-worker-protocol.ts; новые общие transport/preview helper-модули; соответствующие тесты

## Шаги
1. Прочитать AGENTS.md, PRODUCT.md, docs/ARCHITECTURE.md, релевантные спецификации и существующий код.
2. Воспроизвести оставшиеся проблемы тестами, отметить уже реализованные пункты.
3. Согласовать внутренние API с соседними агентами; менять только свою зону.
4. Реализовать небольшими проверяемыми изменениями без новых зависимостей.
5. Запустить целевые тесты, typecheck и lint; отчитаться координатору с файлами, командами, результатами и ограничениями.

## Критерии приёмки
Восемь ориентаций/ошибки EXIF, целостность исходника, source-bound reader, все pending завершаются один раз на error/cancel/messageerror; нет зависаний/лишнего хеша проверенного источника.

Оригинальные байты JPEG неизменны; текущие инструменты, режимы экспорта и Undo/Redo сохранены. Изменения внутренних контрактов, прямо предусмотренные REFACTOR.md, входят в запрос пользователя; новые зависимости/поддержку JPEG не расширять.
