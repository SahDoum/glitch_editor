# Типизированная история и надёжный файл проекта

Источник: `docs/REFACTOR.md`, обновлённая ветка `e497517`.

## Цель
Упростить реальные JPEG-записи/реестр и сборку плана; убрать лишнюю replay-работу и случайный генератор из JPEG-пути; проверять лимит активных команд для всех переходов до мутации. Единый парсер записей и актуальная схема проекта; UTF-8 лимит, явная сборка JSON, протокол Worker, корректный round-trip. Удалять старые пути только после проверки реальных потребителей и согласования с владельцем App.

## Зона ответственности
src/operations/history.ts; src/operations/schema.ts; src/application/jpeg-document.ts; src/project/**; старые хранилища рецептов/кистей; соответствующие тесты

## Шаги
1. Прочитать AGENTS.md, PRODUCT.md, docs/ARCHITECTURE.md, релевантные спецификации и существующий код.
2. Воспроизвести оставшиеся проблемы тестами, отметить уже реализованные пункты.
3. Согласовать внутренние API с соседними агентами; менять только свою зону.
4. Реализовать небольшими проверяемыми изменениями без новых зависимостей.
5. Запустить целевые тесты, typecheck и lint; отчитаться координатору с файлами, командами, результатами и ограничениями.

## Критерии приёмки
Apply→Save→Open→restore проходит для включённых/выключенных операций, масок и стадий; некорректная актуальная версия отличается от неподдерживаемой; ошибки не мутируют историю; Undo/Redo и лимиты проверены.

Оригинальные байты JPEG неизменны; текущие инструменты, режимы экспорта и Undo/Redo сохранены. Изменения внутренних контрактов, прямо предусмотренные REFACTOR.md, входят в запрос пользователя; новые зависимости/поддержку JPEG не расширять.

## Приёмка
Субагент пишет READY_FOR_REVIEW, координатор независимо проверяет diff и тесты, возвращает замечания или ставит ACCEPTED. Не коммитить и не выполнять git reset/checkout.
